# Portfolio Reflection

# 1. Interpreting User Needs & User Stories
I interpret user needs by focusing on the actual goal someone is trying to accomplish rather than jumping straight into features. Writing user stories helps break big, vague requests into clear, manageable tasks written from the user's perspective (*"As a... I want to... so that..."*). Including clear acceptance criteria makes sure I know exactly what "done" looks like before writing any code, which prevents building the wrong thing.

# 2. Approach to Development & Agile Practices
I approach software development iteratively—building small, working parts of a program, testing them, and improving them step-by-step instead of trying to write everything all at once. Going forward, the main Agile practices I plan to keep using are sprint retrospectives and daily stand-ups. Retrospectives are huge for figuring out what slowed the team down, and short daily check-ins keep everyone aligned without wasting hours in unnecessary meetings.

# 3. Being a Good Team Member
Being a good team member in software development comes down to clear communication, accountability, and openness to feedback. It means writing code that is easy for someone else to read and maintain, speaking up early when you're blocked on a problem, and using code reviews to learn rather than being defensive. A reliable developer doesn't just write working code; they make it easier for the whole team to move forward.
